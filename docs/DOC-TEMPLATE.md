# [Feature or system name]

Explain what this helps the reader do in one or two sentences.

**Status:** Implemented / in progress / planned. **Audience:** Who should read this.

## At a glance

Give the main behavior, where the code lives, and the most important limit. Use a
small table when it makes choices easier to compare.

## How it works

Walk through one real user or developer journey. Introduce technical terms where
they become useful. A small diagram can replace a long explanation.

## Key choices

Explain the reason for each important choice and its tradeoff. Keep current
behavior separate from future ideas.

## Try it

List prerequisites, then commands that can be copied and run. Explain the expected
result and the most useful recovery step. Omit this section for a concept guide.

## What we checked

Link tests, evidence and relevant CI runs. State the scope of coverage and the date
of any snapshot. Do not turn targets, mocks or plans into measured results.

## Limits and next steps

Name unresolved questions and the next test or decision that will answer them.

## Read next

Link related guides and primary sources. Keep links close to the claims they help
explain. Use English in docs; keep bilingual UI examples clearly marked as examples.
